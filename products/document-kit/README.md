# مولّد قوالب المستندات — نموذج عامل

**ما هو:** مولّد مبني على قالب واحد + ملف إعدادات لكل تنويعة، ينتج PDF جاهز للطباعة بجودة احترافية.

## البنية

```
build/template.mjs   قالب HTML/CSS — التصميم كله هنا
build/render.mjs     المولّد (Playwright + Chromium)
build/fonts/         Inter + Fraunces — مرخّصة OFL للاستخدام التجاري
config/*.json        ملف لكل تنويعة قطاعية — النصوص والألوان فقط
out/                 المخرجات
```

## التشغيل

```bash
node build/render.mjs                    # كل التنويعات
node build/render.mjs marketing-agency   # واحدة
```

## ماذا يُثبت هذا النموذج

| ✅ مؤتمت بالكامل | ❌ ليس مؤتمتاً |
|---|---|
| التخطيط والتايبوغرافي ونظام الألوان | ملفات PSD / INDD / EPS *(صيغ Envato)* |
| PDF جاهز للطباعة بمقاس A4 | ملفات Canva *(تُبنى داخل واجهة Canva)* |
| **تنويعة جديدة = ملف JSON فقط** | — |
| النصوص والبنود عبر الذكاء الاصطناعي | — |

**التنويعة الإضافية تكلف دقائق لا ساعات** — وهذا هو الفارق الحقيقي: من يصمم يدوياً يطلق ٥ منتجات، وهذا الخط يطلق ٥٠.

## القيد الحاسم

**هذا الخط ينتج PDF، لا PSD ولا INDD ولا Canva.**

فلا يصلح لـ GraphicRiver (يشترط PSD/INDD/EPS بنمط CMYK و300DPI). ويصلح لفئات المنتجات التي **يكون الـPDF فيها هو المنتج نفسه** أو التي تقبل صيغاً نصية.

> **الخلاصة العملية:** لا تختر السوق ثم تحارب الصيغة. **اختر السوق الذي صيغته قابلة للتوليد** — عندها تتحول الأتمتة من ترف إلى ميزة تنافسية مركّبة.

## توليد DOCX

`python-docx` منصّب ويولّد ملفات صالحة، **لكن معاينتها محلياً غير ممكنة** — LibreOffice في هذه البيئة يفشل في التحويل (`source file could not be loaded`، وينقصه Java). **جودة تصميم الـDOCX لم تُتحقق بعد.**
